# 4.1 플랫폼별 성과 차트(Donut) 설계

## 배경

`docs/mobidays_fe_assignment_guide.md`의 `4.1 플랫폼별 성과 차트`는 선택 과제이지만, 상위 글로벌 필터와 양방향으로 연결되는 점 때문에 단순한 시각화 위젯이 아니라 필터 오케스트레이션 위젯으로 봐야 한다.

현재 코드베이스에는 다음 기반이 이미 존재한다.

- 전역 필터 atom과 `useDashboardData(filter)` 기반 조회 흐름
- MSW 기반의 브라우저 메모리 데이터 소스
- `recharts` 기반 공용 차트 래퍼
- `jotai`로 관리되는 글로벌 필터 상태

따라서 이 기능은 별도 API를 새로 만들기보다, 이미 존재하는 `campaigns`와 `dailyStats` 조회 결과를 플랫폼 축으로 다시 집계해 보여주는 방식이 적합하다.

## 목표

- `비용 / 노출수 / 클릭수 / 전환수` 4개 메트릭을 토글할 수 있는 도넛 차트를 제공한다.
- 기본 선택 메트릭은 `비용`으로 고정한다.
- 플랫폼별 비중과 절대값을 동시에 보여주되, 현재 UI의 기본 표시 대상은 `Google / Meta / Naver` 3종으로 둔다.
- 도넛 조각 클릭으로 상단 글로벌 `매체` 필터를 토글한다.
- 글로벌 필터 상태가 변경되면 차트 상태도 즉시 다시 계산된다.
- 차트 렌더링과 계산 로직을 분리해 테스트 가능성을 확보한다.

## 비목표

- 새로운 서버 API 추가
- 플랫폼별 트렌드 라인 차트 추가
- 메트릭 다중 선택
- 플랫폼 수의 동적 확장
- 차트 클릭 외의 별도 필터 UI 추가

## 핵심 결정

### 1. 글로벌 필터를 단일 진실 공급원으로 둔다

플랫폼 선택 상태는 차트 내부에 따로 저장하지 않는다.

- 현재 선택된 플랫폼 집합은 `globalFilterAtom.platforms`를 그대로 따른다.
- 차트는 이 값을 읽어서 선택 상태를 표현한다.
- 차트 클릭은 `toggleGlobalFilterPlatformAtom`을 통해 전역 필터를 갱신한다.

이 방식이면 외부에서 글로벌 필터가 바뀌어도 차트와 상단 필터가 어긋나지 않는다.

### 2. 메트릭 토글은 로컬 상태로 둔다

플랫폼 선택은 전역 상태, 메트릭 선택은 위젯 로컬 상태로 분리한다.

- 메트릭은 단일 선택만 허용한다.
- 기본값은 `cost`다.
- 메트릭 토글은 `비용 / 노출수 / 클릭수 / 전환수` 4개를 모두 렌더링해야 한다.
- 사용자가 다른 메트릭을 선택하면 즉시 도넛 수치와 비중을 다시 계산한다.

메트릭은 글로벌 필터가 아니므로 전역 상태에 넣지 않는다.

### 3. 집계는 현재 전역 필터 결과를 기준으로 수행한다

차트 데이터는 `useDashboardData(filter)` 결과를 입력으로 받아 플랫폼별로 재집계한다.

- `campaigns`와 `dailyStats`는 현재 글로벌 필터가 이미 적용된 상태를 기준으로 계산한다.
- 플랫폼 집계는 데이터에 존재하는 플랫폼 키를 기준으로 수행하고, 표시 우선순위만 `Google / Meta / Naver` 순서로 둔다.
- 현재 명세상 기본 표시 대상은 `Google / Meta / Naver` 3종이지만, 새 매체가 추가돼도 집계 로직이 깨지지 않아야 한다.
- 특정 플랫폼에 데이터가 없더라도 해당 플랫폼은 0으로 유지한다.

이렇게 하면 도넛 비교 축이 흔들리지 않는다.

이 구조의 목적은 현재 과제 범위를 유지하면서도, 나중에 매체가 늘어나면 집계나 필터 동작을 다시 뜯어고치지 않도록 하는 데 있다.

### 4. 차트 클릭은 토글 동작으로 정의한다

도넛 조각 클릭은 선택/해제를 모두 지원하는 토글 동작이다.

- 이미 선택된 플랫폼이면 해제한다.
- 선택되지 않은 플랫폼이면 추가한다.
- 이 동작은 상단 글로벌 매체 필터와 정확히 동일해야 한다.

즉, 도넛은 필터와 별개의 상태를 만들지 않고, 필터를 직접 조작하는 입력 장치로 동작한다.

## 책임 경계

- `entities` 레이어
  - 플랫폼별 집계 로직
  - 메트릭별 값 추출
  - 비중 계산
  - 숫자 정규화와 null 안전 처리
- `widgets` 레이어
  - 메트릭 토글 UI
  - 도넛 차트 렌더링
  - 범례와 툴팁 표현
  - 글로벌 필터와의 상호작용

차트 위젯은 계산 로직을 직접 품지 않고, 계산 결과만 소비한다.

## 데이터 계약

### 입력

차트는 다음 의미를 가진 정규화된 데이터만 필요로 한다.

```ts
type PlatformKey = string;

type PlatformMetricKey = "cost" | "impressions" | "clicks" | "conversions";

interface PlatformPerformancePoint {
	platform: PlatformKey;
	value: number;
	percentage: number;
	isSelected: boolean;
}
```

실제 구현에서 세부 필드는 달라질 수 있지만, 의미는 다음을 유지해야 한다.

- `value`: 선택한 메트릭의 플랫폼별 절대값
- `percentage`: 전체 합계 대비 비중
- `isSelected`: 현재 글로벌 매체 필터와의 동기화 결과
- `platform`: 실제 데이터에 존재하는 플랫폼 키를 그대로 사용하되, 기본 표시 순서는 현재 과제 범위의 플랫폼을 우선한다

### 출력

차트는 아래 정보를 화면에 노출해야 한다.

- 메트릭 토글 상태
- 도넛 중앙의 현재 메트릭명
- 각 플랫폼의 수치
- 각 플랫폼의 비중
- 툴팁의 상세 수치

## 집계 규칙

### 메트릭별 집계

선택한 메트릭에 따라 플랫폼별 합계를 계산한다.

- `cost`: 집행 비용 합계
- `impressions`: 노출수 합계
- `clicks`: 클릭수 합계
- `conversions`: 전환수 합계

집계 대상 플랫폼은 고정 배열이 아니라 데이터에 등장한 플랫폼 키 집합이다. 다만 현재 과제 화면에서는 `Google / Meta / Naver`를 우선순위 상단에 배치한다.

### null 및 비정상 값 처리

데이터 원본에는 예외 상황이 포함될 수 있으므로, 집계 단계에서 안전하게 처리한다.

- `null`은 합계에서 제외한다.
- 숫자가 아닌 값은 제외한다.
- 합계 결과가 없으면 `0`으로 본다.
- 분모가 0이면 비중은 `0%`로 표시한다.

### 비중 계산

```ts
platformPercentage = platformValue / totalValue * 100
```

단, `totalValue === 0`이면 모든 플랫폼 비중은 `0`으로 고정한다.

### 표기 규칙

- `cost`: 원화 정수 표기
- `impressions / clicks / conversions`: 천 단위 구분 정수 표기
- `percentage`: 소수점 1자리까지 표기

합계가 반올림으로 인해 정확히 `100%`가 되지 않아도 허용한다.

## 인터랙션 규칙

### 메트릭 토글

- 4개 토글을 모두 렌더링한다.
- 기본 선택값은 `비용`이다.
- 단일 선택만 허용한다.
- 현재 선택 메트릭은 버튼 상태와 도넛 중앙 문구에 모두 반영한다.

### 도넛 클릭

- 차트 조각 클릭 시 해당 플랫폼을 글로벌 매체 필터에 토글 반영한다.
- 선택된 조각은 시각적으로 강조하고, 미선택 조각은 상대적으로 약하게 표시한다.

### 글로벌 필터 동기화

- 글로벌 매체 필터가 외부에서 바뀌면 차트의 선택 상태도 즉시 다시 계산한다.
- 차트는 필터의 보조 상태가 아니라 필터의 표현이므로, 로컬에 별도 선택 상태를 저장하지 않는다.

## UI 요구

- 카드형 위젯으로 구성한다.
- 헤더에 제목과 간단한 설명을 둔다.
- 본문에는 도넛 차트와 범례를 함께 배치한다.
- 도넛 중앙에는 현재 메트릭명을 표시한다.
- 범례에는 플랫폼명, 수치, 비중을 함께 표시한다.
- 툴팁에는 플랫폼명, 절대값, 비중을 함께 표시한다.

권장 문구는 다음과 같다.

- 제목: `플랫폼별 성과`
- 설명: `현재 필터 기준으로 플랫폼별 기여도를 확인합니다.`

## 접근성 기준

- 메트릭 토글은 버튼으로 제공하고 현재 선택 상태를 `aria-pressed`로 노출한다.
- 차트 조각만으로 정보가 전달되지 않도록 범례 텍스트를 함께 제공한다.
- 툴팁은 마우스 오버 보조 정보로 두고, 핵심 수치는 본문 텍스트에서도 읽을 수 있어야 한다.
- 색상만으로 선택 상태를 구분하지 말고, 투명도나 스트로크 차이 같은 비색상 신호를 함께 쓴다.

## 예외 처리

- 필터 결과에 해당하는 데이터가 없으면 empty state를 보여준다.
- 전체 합계가 0이면 도넛은 렌더링하되 모든 비중을 0으로 표시한다.
- 차트 데이터가 유효하지 않으면 오류 대신 empty state 또는 0 상태로 안전하게 처리한다.
- 불완전한 데이터가 섞여 있어도 위젯 전체가 깨지지 않아야 한다.
- 알려지지 않은 플랫폼 키가 들어와도 집계에서 무시하지 말고, 가능한 범위에서 별도 조각 또는 범용 범례 항목으로 안전하게 표시한다.

## 테스트 기준

- 메트릭 토글 4개 `비용 / 노출수 / 클릭수 / 전환수`가 모두 렌더링되는지 검증한다.
- 기본 선택 메트릭이 `비용`인지 검증한다.
- 선택된 메트릭에 대한 플랫폼별 집계 결과가 정확한지 검증한다.
- 도넛 조각 클릭이 글로벌 매체 필터를 토글하는지 검증한다.
- 글로벌 필터 외부 변경 시 차트 선택 상태와 집계 결과가 다시 동기화되는지 검증한다.
- `null`, 0, 비정상 숫자 입력이 집계와 비중 계산을 깨지 않는지 검증한다.

## 구현 메모

- 글로벌 필터는 `src/entities/global-filter/model/store.ts`의 기존 atom 패턴을 그대로 따른다.
- 차트 전용 집계는 `entities`에 두고, 렌더링은 `widgets`에서 담당한다.
- 메트릭 토글은 기존 `daily-trend-chart`의 선택 패턴과 유사하지만, 이번에는 단일 선택으로 고정한다.
- 차트 클릭과 필터 토글은 같은 의미를 가져야 하므로, UI 이벤트와 store action의 이름을 일치시키는 편이 좋다.
- 플랫폼 메타데이터는 하드코딩 3개 상수보다 `platform -> label / color / order` 매핑 형태로 분리하는 편이 확장에 유리하다.
