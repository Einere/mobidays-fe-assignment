# 3.2 일별 추이 차트 설계

## 배경

`docs/mobidays_fe_assignment_guide.md`의 3.2 요구사항은 전역 필터와 동기화되는 일별 추이 차트를 요구합니다. 현재 코드베이스에는 전역 필터 atom, MSW 기반 조회 흐름, `useDashboardData(filter)` 훅이 이미 존재하므로, 이번 작업은 기존 조회 결과 위에 날짜 집계 레이어와 차트 위젯을 추가하는 방식이 가장 자연스럽습니다.

또한 현재 `App.tsx`의 "성과 개요" 패널은 placeholder 성격의 카드이며, 상단 영역을 넓게 재구성할 여지가 있습니다. 따라서 이 패널을 차트 중심 패널로 전환하고, 보조 성격의 "상태 규칙" 패널은 하단으로 이동합니다.

## 목표

- 전역 필터 결과에 따라 자동으로 갱신되는 일별 추이 차트를 제공한다.
- 차트 유형은 꺾은선 그래프(`LineChart`)로 고정한다.
- 차트는 X축 날짜, Y축 수치, 범례, 툴팁을 모두 포함한다.
- 메트릭 토글은 UI상 `노출수`, `클릭수`를 제공하되, 내부 구조는 `전환수`, `집행비용`까지 확장 가능하게 설계한다.
- `null`과 `0`을 구분하여 표현한다. 값이 없으면 0으로 치환하지 않고 뷰에서 `-`로 드러낸다.

## 범위

### 포함

- `shadcn`의 Recharts v3 기반 공용 차트 컴포넌트 도입
- 날짜별 시계열 집계 순수 함수 추가
- 일별 추이 차트 위젯 추가
- `App.tsx` 상단 레이아웃 재배치
- 차트 메트릭 토글, 범례, 툴팁, 빈 상태/오류 상태 처리
- 차트 관련 단위 테스트 및 위젯 테스트

### 제외

- 선택 과제 차트 구현
- 테이블/모달 요구사항 구현
- 차트 메트릭 UI에 `전환수`, `집행비용` 즉시 노출
- 서버 API 스펙 변경

## 사용자 흐름

1. 사용자가 전역 필터의 기간, 상태, 매체를 변경한다.
2. `useDashboardData(filter)`가 새로운 query key로 재조회한다.
3. 조회된 `dailyStats`를 날짜 기준으로 집계하여 차트용 시계열 데이터로 변환한다.
4. 차트 위젯은 선택된 메트릭만 라인으로 렌더링한다.
5. 사용자가 메트릭 토글을 조작하면 선택된 라인만 즉시 갱신된다.
6. 사용자가 특정 날짜를 호버하면 해당 날짜의 메트릭 수치를 툴팁에서 확인한다.

## 설계 원칙

### 1. 조회와 집계의 책임 분리

조회 책임은 기존 `useDashboardData(filter)`에 유지합니다. 차트를 위해 별도 API를 만들지 않습니다. 차트 전용 계산은 `entities/daily-stat`의 순수 함수로 분리하여 테스트 가능한 단위로 고정합니다.

### 2. 전역 상태와 위젯 상태의 분리

전역 필터는 기존 `globalFilterAtom`이 단일 진실 공급원으로 유지합니다. 반면 메트릭 토글은 차트 위젯 전용 인터랙션이므로 위젯 로컬 상태로 둡니다. 이 상태는 테이블, 다른 위젯, 전역 필터와 공유하지 않습니다.

### 3. `null`과 `0`의 의미 보존

데이터가 없음을 뜻하는 `null`은 실제 값 `0`과 다릅니다. 따라서 차트 집계 과정에서 `null`을 `0`으로 변환하지 않습니다. 날짜별 특정 메트릭에 유효한 숫자가 하나도 없으면 집계 결과도 `null`로 남깁니다. 차트에서는 라인이 끊기고, 툴팁 및 보조 텍스트에서는 `-`로 표시합니다.

### 4. 확장 가능한 메트릭 모델

현재 UI는 과제 명세대로 `노출수`, `클릭수`만 노출합니다. 하지만 내부 메트릭 정의는 `impressions`, `clicks`, `conversions`, `cost`를 모두 포함합니다. 이렇게 하면 4.1, 4.2 또는 이후 고도화 시 동일한 집계 모델을 재사용할 수 있습니다.

### 레이아웃

- 상단 메인 영역: 넓은 `성과 개요` 패널
- 패널 내부:
  - 제목/설명
  - 메트릭 토글 그룹
  - 범례
  - 일별 추이 꺾은선 그래프
- 하단 보조 영역: 기존 `상태 규칙` 패널

### 차트 카드 헤더

- 제목: `성과 개요`
- 설명: 전역 필터 기준으로 집계된 일별 성과 흐름을 보여준다는 문구
- 우측 제어 영역: 메트릭 토글 버튼

## 데이터 모델

### 입력

- `DashboardData.campaigns`
- `DashboardData.dailyStats`

차트는 실제로 `dailyStats`를 주로 사용하지만, 빈 상태나 설명 문구에서 캠페인 수를 보조적으로 활용할 수 있습니다.

### 내부 메트릭 타입

```ts
type DailyTrendMetricKey =
	| "impressions"
	| "clicks"
	| "conversions"
	| "cost";
```

### 날짜별 집계 결과 타입

```ts
interface DailyTrendPoint {
	date: string;
	impressions: number | null;
	clicks: number | null;
	conversions: number | null;
	cost: number | null;
}
```

### 메트릭 메타 정보

```ts
interface DailyTrendMetricDefinition {
	key: DailyTrendMetricKey;
	label: string;
	colorToken: string;
}
```

UI에 실제 노출하는 기본 메트릭 정의는 아래 두 개입니다.

```ts
[
	{ key: "impressions", label: "노출수", colorToken: "var(--chart-positive)" },
	{ key: "clicks", label: "클릭수", colorToken: "var(--chart-info)" },
]
```

## 집계 규칙

### 날짜 그룹핑

- `dailyStats`를 `date` 기준으로 그룹핑합니다.
- 날짜는 오름차순 정렬합니다.
- `date`가 `null`이거나 파싱 가능한 날짜가 아니면 제외합니다.

### 메트릭 합산

각 날짜 그룹에서 메트릭별로 아래 규칙을 적용합니다.

- 유효한 숫자만 합산합니다.
- `null`은 합산에 포함하지 않습니다.
- 해당 날짜에 유효한 숫자가 하나도 없으면 결과는 `null`입니다.
- 유효한 숫자가 하나 이상 있으면 그 합계를 결과로 사용합니다.

예시:

```ts
[
	{ date: "2024-01-01", impressions: 100, clicks: null },
	{ date: "2024-01-01", impressions: 50, clicks: 10 },
];
```

집계 결과:

```ts
{ date: "2024-01-01", impressions: 150, clicks: 10 }
```

모든 `clicks`가 `null`이었다면 집계 결과의 `clicks`도 `null`입니다.

## UI 동작

### 메트릭 토글

- 초기값은 `노출수`, `클릭수` 모두 선택
- 복수 선택 가능
- 마지막 1개는 해제할 수 없음
- 현재는 두 메트릭만 렌더링하지만, 토글 로직은 일반화된 메트릭 배열 기반으로 작성

### 범례

- 선택된 메트릭만 범례에 노출
- 색상은 각 메트릭 정의의 토큰을 사용
- 범례 텍스트는 한국어 라벨 사용

### 툴팁

- 호버한 날짜 표시
- 선택된 메트릭별 값 표시
- 값이 `null`이면 `-`
- 숫자 포맷은 메트릭별 문맥에 맞춘다
  - `impressions`, `clicks`, `conversions`: 정수 천 단위 구분
  - `cost`: 원화 포맷

### 라인 렌더링

- 차트 구현은 Recharts `LineChart`를 사용
- 선택된 메트릭마다 라인 1개 렌더링
- 값이 `null`인 지점은 0으로 찍지 않음
- `connectNulls`는 사용하지 않아 선이 끊기도록 유지

## 상태별 처리

### 로딩 상태

- 기존 query의 `isPending` 또는 초기 로딩 상태에서 차트 영역에 스켈레톤 또는 자리표시 영역을 표시
- 레이아웃 점프를 줄이기 위해 차트 높이는 고정

### 재조회 상태

- `isFetching`일 때 기존 차트를 유지하면서 보조 텍스트 또는 패널 상태로 "동기화 중"을 드러냄

### 오류 상태

- 조회 실패 시 차트 대신 오류 메시지와 재시도 문맥을 제공
- 문구는 현재 `GlobalFilterSummary`의 상태 표현과 어조를 맞춤

### 빈 상태

다음 두 경우를 구분합니다.

1. 필터 결과 캠페인이 0건인 경우
2. 캠페인은 있으나 차트에 표시할 유효한 일별 데이터가 없는 경우

두 경우 모두 차트 대신 안내 문구를 보여주되, 메시지는 원인을 구분합니다.

## 테스트 전략

### 단위 테스트: 집계 함수

검증할 시나리오:

- 여러 캠페인의 같은 날짜 값을 합산한다.
- 날짜가 오름차순으로 정렬된다.
- `null`만 존재하는 메트릭은 결과도 `null`이다.
- `0`과 `null`을 구분한다.
- `date`가 `null`인 항목은 제외한다.

### 위젯 테스트

검증할 시나리오:

- 초기 상태에서 `노출수`, `클릭수`가 모두 활성화된다.
- 마지막 하나의 메트릭은 비활성화할 수 없다.
- query 성공 시 선택된 메트릭 라인이 렌더링된다.
- 빈 상태 메시지가 원인에 맞게 표시된다.
- 오류 상태 메시지가 표시된다.
- 툴팁 값 포맷에서 `null`은 `-`로 표현된다.

### 레이아웃 확인

- `App.tsx`에서 `성과 개요` 패널이 넓은 메인 패널로 배치된다.
- `상태 규칙` 패널은 하단으로 이동한다.

## 접근성

- 메트릭 토글은 버튼으로 구현하고 `aria-pressed` 상태를 반영합니다.
- 차트 제목과 설명은 텍스트로 제공하여 차트 의미를 텍스트만으로도 파악할 수 있게 합니다.
- 로딩/오류/빈 상태는 스크린리더가 읽을 수 있는 텍스트를 포함합니다.
- 색상만으로 메트릭을 구분하지 않고 범례 라벨을 함께 제공합니다.

## 리스크와 대응

### 1. shadcn chart 스타일이 기존 디자인 토큰과 충돌할 수 있음

공용 래퍼에서 토큰 매핑을 한 번 감싸고, 위젯은 그 래퍼만 사용하도록 제한합니다.

### 2. `null` 데이터 표현이 Recharts 기본 동작과 어긋날 수 있음

집계 결과 타입을 `number | null`로 유지하고, 라인 연결 옵션을 명시적으로 비활성화합니다.

### 3. 차트와 필터 재조회 시 레이아웃 점프가 발생할 수 있음

패널과 차트 컨테이너 최소 높이를 고정해 시각적 흔들림을 줄입니다.

## 완료 기준

- 전역 필터 변경 시 차트가 같은 조회 흐름 안에서 자동 갱신된다.
- 차트는 꺾은선 그래프로 렌더링된다.
- X축, Y축, 범례, 툴팁이 모두 보인다.
- 메트릭 토글은 초기 2개 선택, 복수 선택, 최소 1개 유지 규칙을 만족한다.
- `null`은 0으로 치환되지 않고 차트와 툴팁에서 의미 있게 표현된다.
- 상단 레이아웃이 `성과 개요` 중심으로 재구성된다.
- 관련 단위 테스트와 위젯 테스트가 추가된다.
