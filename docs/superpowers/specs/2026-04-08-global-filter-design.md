# 글로벌 필터 설계

## 배경

`docs/mobidays_fe_assignment_guide.md`의 `3.1 글로벌 필터`는 대시보드 전체 데이터 집합을 결정하는 기준 상태입니다. 사용자가 집행 기간, 상태, 매체를 변경하면 하위 차트와 테이블이 동일한 기준 데이터에 동기화되어야 합니다.

이번 설계는 `3.1 글로벌 필터` 자체의 책임만 다룹니다. 차트, 테이블, 요약 위젯의 구체 구현은 범위에 포함하지 않지만, 이후 위젯들이 어떤 입력을 받아야 하는지는 이 문서에서 고정합니다.

## 목표

- 글로벌 필터의 상태 모델을 명확히 정의한다.
- 필터 UI의 데스크톱/모바일 동작을 명확히 정의한다.
- 데이터 필터링 책임을 서버 레이어(MSW)로 고정한다.
- 캠페인 관리 테이블 전용 상태와 글로벌 필터 상태의 경계를 분리한다.
- 빈 결과, 잘못된 날짜 범위 같은 예외 상황의 처리 기준을 정의한다.

## 비목표

- `3.2 일별 추이 차트`의 구체 렌더링 구현
- `3.3 캠페인 관리 테이블`의 컬럼/정렬/검색/페이지네이션 구현
- `3.4 캠페인 등록 모달` 구현
- 선택 구현 항목인 플랫폼별 성과 차트, 랭킹 Top3 구현

## 책임 경계

글로벌 필터는 "무슨 데이터를 가져올지"를 결정합니다. 필터 상태가 변경되면 클라이언트는 서버에 필터 조건을 전달하고, 서버 레이어는 해당 조건에 맞는 `campaigns`와 `daily_stats`를 반환합니다.

반면 캠페인 관리 테이블의 검색어, 정렬 상태, 페이지 번호, 체크박스 선택 상태는 "가져온 데이터를 어떻게 보여줄지"에 해당하므로 클라이언트 로컬 상태로 관리합니다. 이 로컬 상태는 차트나 다른 위젯에 영향을 주지 않습니다.

정리하면 다음과 같습니다.

- 글로벌 필터: 서버 질의 조건
- 테이블 로컬 상태: 렌더링 후처리 조건

## 상태 모델

글로벌 필터의 canonical state는 아래 3개 필드만 가집니다.

```ts
type CampaignStatus = "active" | "paused" | "ended";
type CampaignPlatform = "Google" | "Meta" | "Naver";

interface GlobalFilterState {
	dateRange: {
		startDate: string; // YYYY-MM-DD
		endDate: string; // YYYY-MM-DD
	};
	statuses: CampaignStatus[];
	platforms: CampaignPlatform[];
}
```

초기값은 과제 명세를 그대로 따릅니다.

```ts
const initialGlobalFilterState: GlobalFilterState = {
	dateRange: {
		startDate: "<당월 1일>",
		endDate: "<당월 말일>",
	},
	statuses: ["active", "paused", "ended"],
	platforms: ["Google", "Meta", "Naver"],
};
```

상태 배열은 "전체" 의미를 숨긴 특수값으로 해석하지 않습니다. 전체 선택은 모든 항목이 실제로 배열에 들어 있는 상태로 표현합니다.

이 규칙을 택한 이유는 다음과 같습니다.

- 상태 값만 봐도 현재 의미를 즉시 이해할 수 있습니다.
- 서버 요청 직렬화 규칙이 단순합니다.
- 테스트에서 "빈 배열은 전체" 같은 암묵 규칙이 사라집니다.

## UI 구조

### 데스크톱

- 집행 기간: `시작일` / `종료일` 2개 입력
- 상태: 인라인 칩 멀티셀렉트
- 매체: 인라인 칩 멀티셀렉트
- 초기화: 필터 영역 우측 액션 버튼

### 모바일

- 집행 기간: `시작일` / `종료일` 2개 입력
- 상태: 드롭다운 안 체크박스 목록
- 매체: 드롭다운 안 체크박스 목록
- 초기화: 필터 영역 하단 또는 헤더 우측 액션 버튼

데스크톱과 모바일은 표현 방식만 다르고 동일한 상태를 공유합니다.

## UI 인터랙션 규칙

### 집행 기간

- `시작일`과 `종료일`은 독립 입력이지만 하나의 `dateRange` 상태를 갱신합니다.
- 사용자가 날짜를 변경했을 때 범위가 유효하면 해당 값으로 필터를 갱신합니다.
- `시작일 > 종료일`이면 에러를 즉시 노출하고, 마지막으로 유효했던 필터 상태를 유지합니다.
- 초기화 시 `당월 1일 ~ 당월 말일`로 복구합니다.

### 상태/매체 멀티셀렉트

- 데스크톱 칩과 모바일 체크박스는 동일한 선택 의미를 가집니다.
- 전체 선택은 별도 저장값이 아니라 "모든 값이 배열에 포함된 상태"를 의미합니다.
- `전체`를 누르면 해당 그룹 배열을 전체 값 목록으로 재설정합니다.
- 개별 항목을 해제하면 `전체`의 시각 상태는 해제됩니다.
- 개별 항목을 다시 모두 선택하면 `전체`의 시각 상태가 자동으로 복귀합니다.
- 마지막 1개 항목도 해제할 수 있습니다.
- 항목이 0개 선택된 상태는 유효하며, 결과 0건을 의미합니다.

### 초기화

초기화 버튼은 아래 상태를 한 번에 복구합니다.

- 기간: 당월 1일 ~ 당월 말일
- 상태: `["active", "paused", "ended"]`
- 매체: `["Google", "Meta", "Naver"]`

## 필터 적용 규칙

필터 조건은 모두 `AND`로 조합합니다.

1. 선택한 집행 기간과 겹치는 캠페인만 포함합니다.
2. 그중 선택된 상태 집합에 속한 캠페인만 포함합니다.
3. 그중 선택된 매체 집합에 속한 캠페인만 포함합니다.
4. 최종 캠페인 집합에 속한 `daily_stats` 중 선택 기간 안의 데이터만 집계 대상으로 포함합니다.

### 캠페인 필터 조건

집행 기간은 "선택한 기간과 겹쳐서 집행 중인 캠페인" 기준으로 해석합니다.

```ts
campaign.startDate <= filter.endDate &&
(campaign.endDate === null || campaign.endDate >= filter.startDate)
```

상태/매체는 각각 배열 포함 여부로 판별합니다.

```ts
filter.statuses.includes(campaign.status) &&
filter.platforms.includes(campaign.platform)
```

따라서 이번 설계에서 빈 배열은 "전체"가 아니라 "선택 없음"입니다. `statuses` 또는 `platforms`가 빈 배열이면 결과 캠페인 수는 0건이 됩니다.

### 일별 데이터 필터 조건

`daily_stats`는 캠페인 필터 결과와 기간 조건을 함께 만족해야 합니다.

```ts
filteredCampaignIds.includes(dailyStat.campaignId) &&
dailyStat.date >= filter.startDate &&
dailyStat.date <= filter.endDate
```

## 서버 연동 방식

데이터 필터링 책임은 서버 레이어가 가집니다. 클라이언트는 글로벌 필터 상태를 서버 요청 파라미터로 직렬화하고, MSW 핸들러가 필터링된 결과를 반환합니다.

예상 요청 형태는 다음과 같습니다.

```ts
GET /campaigns?startDate=2024-01-01&endDate=2024-01-31&statuses=active,paused&platforms=Google,Meta
GET /daily_stats?startDate=2024-01-01&endDate=2024-01-31&campaignIds=1,2,3
```

흐름은 아래 순서를 따릅니다.

1. 사용자가 글로벌 필터를 변경합니다.
2. 클라이언트가 필터 상태를 query key와 요청 파라미터에 반영합니다.
3. MSW 핸들러가 `campaigns`를 기간/상태/매체 기준으로 필터링합니다.
4. 필터링된 캠페인 ID 집합을 기준으로 `daily_stats`를 기간 내에서 필터링합니다.
5. 하위 위젯은 동일한 필터링 결과 집합을 입력으로 사용합니다.

## 캠페인 관리 테이블과의 관계

캠페인 관리 테이블은 글로벌 필터 결과를 입력으로 받되, 아래 상태는 로컬로 관리합니다.

- 검색어
- 정렬 기준 및 방향
- 페이지 번호
- 체크박스 선택 상태

이 상태들은 서버 요청 파라미터에 포함되지 않으며, 차트나 다른 위젯 데이터에도 영향을 주지 않습니다.

특히 "캠페인명 검색은 테이블에만 적용"이라는 과제 명세를 지키기 위해 검색 상태는 글로벌 필터 상태에 포함하지 않습니다.

## 빈 결과와 예외 처리

빈 결과는 예외가 아니라 정상 상태로 처리합니다.

- 상태/매체를 모두 해제하여 결과 0건이 될 수 있습니다.
- 기간과 겹치는 캠페인이 하나도 없을 수 있습니다.
- 이 경우 차트/테이블/요약 위젯은 이후 구현 단계에서 empty state 또는 `0`/`-` 표기 규칙을 따라야 합니다.

날짜 범위 오류는 즉시 사용자에게 드러나야 합니다.

- `시작일 > 종료일`이면 필터를 적용하지 않습니다.
- 에러 메시지를 표시합니다.
- 마지막으로 유효했던 서버 질의 상태를 유지합니다.

## 테스트 범위

`3.1 글로벌 필터` 단독 범위에서 필요한 테스트는 아래와 같습니다.

- 초기 글로벌 필터가 당월 1일~말일, 전체 상태, 전체 매체로 설정된다.
- 상태 칩 토글 시 선택 배열이 정확히 반영된다.
- 모바일 드롭다운 체크 상태가 동일한 필터 상태와 동기화된다.
- 매체를 모두 해제하면 서버 필터 결과가 0건이 된다.
- 기간이 캠페인 집행 기간과 "겹치는지" 기준으로 캠페인이 필터링된다.
- `daily_stats`는 필터링된 캠페인 ID + 선택 기간 기준으로만 반환된다.
- 초기화 버튼이 모든 필터를 명세 초기값으로 복구한다.
- 잘못된 날짜 범위 입력 시 에러가 노출되고 재조회가 발생하지 않는다.

다음 테스트는 현재 범위에 포함하지 않습니다.

- 테이블 검색/정렬/페이지네이션 상태는 글로벌 필터 상태와 분리된다.
- 차트와 테이블이 동일 기준으로 다시 렌더링되는지 검증하는 통합 테스트

이 항목들은 차트/테이블 위젯이 실제로 구현된 뒤 상위 통합 테스트에서 검증하는 것이 맞습니다.

## 구현 메모

- 글로벌 필터 상태는 Jotai atom으로 관리하는 방향을 유지합니다.
- 서버 필터 로직은 MSW 핸들러 안에 직접 쓰지 않고, `entities` 레이어의 순수 함수로 분리합니다.
- 날짜 계산 초기값은 클라이언트에서 생성하되, 직렬화 포맷은 항상 `YYYY-MM-DD`로 고정합니다.
- 데스크톱/모바일 UI는 상태를 공유해야 하므로, 프레젠테이션 컴포넌트와 상태 바인딩 로직을 분리하는 편이 안전합니다.
